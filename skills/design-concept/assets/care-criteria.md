# Care criteria — what "inevitable" means

On the **selected** expression only (after subtract pass). Craft executes care; this file names what care must protect. Update `briefs.md` **Care** line from here.

## Care block (required on selected card)

```markdown
- **Care — inevitable:** <the detail that proves the mechanism if everything else is quiet>
- **Care — stays quiet:** <what must not compete for attention>
```

## What often proves the mechanism

Pick one primary; secondary stays quiet.

| Proof detail | When it is the Care focus |
|---|---|
| **Empty-state sentence** | First-run teaches the mechanism (not "No data") |
| **The one number** | Job hinges on a running total, Δ, confidence, or count |
| **Undo / reverse** | Forever-adjacent actions; trust depends on recovery |
| **Selected-row / focus clarity** | Dense triage; "where am I?" is the job |
| **Resumption cue** | Interruption is normal; return must feel continuous |

## Quiet by default

Do not let these shout unless they *are* the Care focus:

- Decorative chrome, secondary filters, badge forests
- Multiple equal-weight CTAs
- Status colors (sweep is grayscale; craft later — still one semantic meaning)
- Onboarding tours that repeat every session

## Tie to Desire and Aging

- Inevitable detail should serve **Desire** (feel / become), not only remove friction.
- Quiet list should protect **Aging** (100th use still calm).

## Before you finish

| Mistake | Fix |
|---|---|
| Care = "make it polished" | Name one inevitable proof detail |
| Everything inevitable | Subtract until one leads |
| Empty Care on selected | Fill before handoff to flow/craft |
| Care fights Desire | Rewrite Care to serve Desire |
