# Sandbox card — Desire, materials, aging

Fill this before `define-concept` storms. Constraints are the playground, not a late veto. Copy into `problem.md` and mirror Desire / Sandbox / Aging into `context.md`.

## Desire (required)

One line: what the actor wants to **feel or become** when this works — not only what pain stops.

```markdown
**Desire:** <e.g. feel in control of every exception before the insurer does; look decisive in Friday review>
```

Examples of good Desire: calm under volume · mastery of the edge case · speed-as-identity · "looks like I have the numbers" · trust without babysitting the model.

Bad: "users want it to be easier" (restates pain).

## Sandbox card (required)

```markdown
## Sandbox
| Dimension | What we invent inside |
|---|---|
| **Materials / brand** | Voice, existing product grammar, craft system name (or "none yet") |
| **Platform / system** | Web/desktop/mobile; design-system tokens or house chrome; what already exists as reusable |
| **Complexity budget** | What we can afford this cycle (e.g. one new surface, no new object types, reuse estimate detail) |
| **Non-negotiables** | Legal, security, data honesty, principles that cannot bend |
```

Pull early notes from `model.md` when known (freshness, batch vs realtime). Leave gaps explicit — `Unknown: whether nightly batch is acceptable` — do not invent certainty.

Wild concepts that ignore this card are fiction.

## Aging (required)

One line: what must still feel right on the **100th use** / year two — and what would become annoying.

```markdown
**Aging:** <e.g. bulk resolve stays one gesture; notification noise never becomes the product>
```

Feeds `define-flow` repeat-use and product principles.

## Before you finish

| Mistake | Fix |
|---|---|
| Desire restates friction | Rewrite as feel / become / be seen as |
| Empty sandbox ("TBD") | At least materials + one non-negotiable; mark unknowns |
| Storm before sandbox | Fill this card first |
| No aging line | 100th-use aspiration before Gate 1 |
