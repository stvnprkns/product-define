# Route cards — how much middle this request deserves

Process reduces uncertainty. Announce the class and route before running. Skip with a reason. Re-classify when a phase surprises you.

## Low uncertainty

**Looks like:** known problem, known users, established pattern ("add bulk selection to this table").

**Route:**  
`concept (patterns only; storm skipped — mechanism known) → flow → craft → review (QA)`

**Skip:** discover/deep frame, mechanism storm, validate (unless a new risk appears).

## Medium uncertainty

**Looks like:** problem understood; solution or model uncertain ("improve supplements *in this screen*").

**Route:**  
`frame (frame-only + pressure-test + Desire/sandbox/aging) → model? → concept (patterns + storm + diverge + subtract) → flow → craft → review (QA)`

**Variant:** mechanism already locked, only expression varies →  
`concept (patterns + expression sweep; storm skipped with reason) → …`

## High uncertainty

**Looks like:** user, problem, data, or workflow unclear ("better way to handle supplements").

**Route:**  
`frame (discover + deep-if-triggered + pressure-test + Desire/sandbox/aging) → model (model + IA) → concept (patterns + storm + diverge + subtract) → flow → validate → craft → review (QA)`

**Do not:** skip to concept on Assumed-only evidence — deepen frame per `define-frame` / research-depth.

## Calibration

| Signal | Move |
|---|---|
| Thin evidence | Deepen frame, don't concept |
| Mechanism known | Skip storm; announce why |
| Mechanism uncertain | Full 15–20 storm |
| After cut 2 | Subtract pass + Care before flow |
| Every gate PASS | Prefer PROCEED WITH ASSUMPTION when uncertainty remains |
